# 演示素材

50 张图片：10 种基础图 × 5 组（`a`–`e`），用于批量压缩与并发验证。

## 用法

首次使用先跑一次脚本生成素材（约 5 秒）：

```powershell
python demo-images/make-demo-images.py
```

然后在 ImgZip 里添加整个 `demo-images` 文件夹（会递归处理 50 张），或按组挑选。

5 组内容**字节完全相同**，重新分组是为了让批量任务有足够数量，同时保持每张图的测试意图可追溯。

## 文件说明

每组 10 张，编号含义相同，前缀 `a`–`e` 是组号：

| 文件名 | 尺寸 | 单张体积 | 用来验证 |
| --- | --- | --- | --- |
| `*01-large-photo.jpg` | 6000×4000 | 12.0 MB | 长边缩放到 4000/2560，降采样后压缩收益 |
| `*02-noise-detail.jpg` | 3600×2400 | 11.0 MB | 高细节噪点，不同质量档位差异最明显 |
| `*03-flat-color.jpg` | 2000×1400 | 45 KB | 平坦色块，压缩比极高，不该被压得更大 |
| `*04-chart-text.jpg` | 2600×1700 | 181 KB | 文字与硬边，对比 JPEG/WebP 的块效应 |
| `*05-transparent.png` | 1800×1800 | 20 KB | RGBA 透明通道，保留 PNG 与转格式时的透明度 |
| `*06-alpha-gradient.png` | 1400×1400 | 247 KB | 半透明渐变，有损转换最易出色带 |
| `*07-small-640.jpg` | 640×480 | 17 KB | 小图，验证「不放大」开关 |
| `*08 中文 与 空格.jpg` | 3000×2000 | 201 KB | 中文与空格文件名，路径编码与参数转义 |
| `*09-webp-source.webp` | 1600×1200 | 34 KB | WebP 输入，同格式再压缩与跨格式转换 |
| `*10-portrait-large.jpg` | 3200×5200 | 850 KB | 竖幅，验证「短边缩放」与方向处理 |

## 规模

| 项 | 数值 |
| --- | --- |
| 图片总数 | 50 |
| 目录总计 | 120.6 MB |
| 单组 | 24.1 MB |
| 真实引擎 q90 批量（含递归） | 50 张全部成功，2 秒，-73.1% |

## 非图片文件

- `说明-README.txt` — 普通文件，勾选「复制其他文件」后应被复制到输出目录
- `Thumbs.db` — 系统文件名，应同样被复制而不是被跳过

## 注意

- **图片本身不入库**。`.gitignore` 忽略 `demo-images/*`，只保留本文件和 `make-demo-images.py`，避免 120 MB 二进制进仓库。clone 后跑一次脚本即可。
- `Thumbs.db` 同样被根目录 `.gitignore` 排除（那条规则本意是防真实系统文件入库），重跑脚本可恢复。
- 图片由脚本用固定随机种子 `20261107` 生成，重新运行得到完全相同的字节。先编码 `a` 组再文件复制出 `b`–`e`，因此组间必然一致。
- 脚本生成的是合成图，色调分布接近照片但缺少真实纹理。要测真实场景建议另加手机拍摄的样张。
