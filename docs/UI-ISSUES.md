## 1. 标题栏按钮颜色不对 → 已解决

**现象**：右上角三个按钮在悬停/按下时底色与图标颜色和主题不匹配。

**原因**：`ApplyCaptionTheme()` 只设置了按钮底色与悬停底色，缺少悬停前景、按下底色/前景、非活动前景，这些状态被系统默认值接管。

**修复**：补全 `ButtonHoverForegroundColor`、`ButtonPressedBackgroundColor/ForegroundColor`、`ButtonInactiveForegroundColor`；浅色用 `#E9E9E9/#1F1F1F`、深色用 `#333333/White`；随 `ActualThemeChanged` 重新应用；关闭键保留系统红色悬停。

## 2. 「执行位置」下拉框 → 二选一按钮 → 已解决

**现象**：引擎选择藏在 `ComboBox` 里，交互不直观。

**修复**：改为两个等宽分段按钮（新增 `SegmentLeftButton` / `SegmentRightButton` 样式，选中态使用 `SelectedBrush`/`AccentBrush`）；点击写回 `ViewModel.EngineIndex` 并触发重新探测；NAS 未配置时该项置灰；保留 `CanEdit` 门控与无障碍名称。

## 3. PC 多任务并行 → 已解决

**需求**：PC 引擎支持多任务并行，NAS 维持单任务。

**实现**：新增 `CompressionTaskViewModel` 与 `MainViewModel.Tasks` 任务集合；PC 并发上限取设置项 `PcConcurrency`（0 = 自动 = CPU 核数，可调 1–64）；NAS 任务彼此互斥但可与 PC 任务并行；任务启动时按 `threads = max(1, 核数 / 并行任务数)` 分配引擎线程；任务记录写入 `tasks/<jobId>.json`，启动时恢复待确认任务，旧 `active-job.json` 迁移为待检查任务；主界面底部改为任务列表（逐任务进度、当前文件、取消/重新检查/打开输出/失败详情）；成功任务自动移出列表，失败/取消/待确认保留；草稿区域运行期间保持可编辑，可继续排队；重复来源聚焦已有任务而不重复入队。

**验证**：测试新增“PC 并发上限”“NAS 串行”等用例，当前共 15 项检查全部通过。

## 4. PC 引擎加速（消除逐文件进程开销）→ 已解决

**现象**：每张图片新起一次引擎进程且完全串行，批量任务的大头是固定开销。

**实测（20 张 1.7 MB JPEG，q90）**：逐文件调用 20 次 30.27 秒；单次批量调用 2.39 秒（约 12.7 倍差距，约 1.4 秒/张的进程启动开销，主要来自安全软件扫描引擎可执行文件）。

**修复**：`worker/imgzip-worker.ps1` 的 `Run-Local` 改为按“是否需要 `--format` 转换”分组、组内分批调用引擎（批大小 `clamp(2×核心数, 4, 16)`，批内源文件名判重避免 stage 覆盖）；批次运行中轮询 stage 目录，产物写完（可独占打开）即搬运并逐张上报；批结束后按引擎输出补齐失败项。

**验证**：经 worker 端到端实测 **8.8 秒**（旧实现同规模约 30 秒），逐张进度真实流式（首个完成 2.35 秒、最后一个 8.69 秒）。

## 5. NAS 引擎加速（吃满多核）→ 已解决

**现象**：NAS 侧同样一文件一次调用，且 `--threads` 传 4；实测表明实际只用了 1 个核。

**实测（N5105 4 核 / 7.7 GB，20 张 JPEG，q90，本地磁盘）**：

| 调用方式 | 总耗时 | 相对 |
|---|---|---|
| 逐文件 `--threads 4`（原实现） | 49.74 秒 | 1.00× |
| 单次批量 `--threads 1` | 49.82 秒 | 1.00× |
| 单次批量 `--threads 4` | 15.48 秒 | 3.21× |

**关键结论**：caesiumclt 的 `--threads` 是**作业级**并行，单文件输入时给再多线程仍等于单核。

**修复**：`worker/nas-worker.sh` 的逐文件循环改为按 `THREADS` 并发的进程池——每文件仍在独立 stage 目录里由单个 `--threads 1` 的引擎作业处理、硬链接晋升并逐张上报；子进程继承 runner 的 setsid 会话，因此既有取消（杀进程组）与 unknown 判定语义不变；父进程统一累计计数并按完成顺序输出事件，避免 JSON 行交错。

**验证**：并行数 1 耗时 65.5 秒、并行数 4 耗时 **26.2 秒（2.5×）**，20 个产出、20 个 `file` 事件、终态 succeeded。

## 6. 深色下标题栏白块、按钮不可见 → 已解决

**现象**：深色主题、系统为浅色时，标题栏右侧出现白块，按钮几乎不可见；悬停时才正常。

**排查过程（三次失败尝试，记录以免重走）**：

1. `AppWindow.TitleBar.BackgroundColor / InactiveBackgroundColor`：标准标题栏不接受，只在自绘模式下生效。
2. DWM `DWMWA_CAPTION_COLOR(35)` / `DWMWA_TEXT_COLOR(36)`：调用返回 S_OK，但外观无变化。
3. DWM `DWMWA_USE_IMMERSIVE_DARK_MODE(20)`：置 1 并回读确认，外观依旧无变化。

结论：本环境下**系统绘制的标题栏不接受应用自定义配色**；而按钮类属性（悬停/按下）确实生效，这正是“只有悬停正常”的原因。

**修复**：改为**自绘标题栏**——`ExtendsContentIntoTitleBar = true` + `SetTitleBar(AppTitleBar)`，标题栏区域由应用 XAML 绘制（跟随主题取 `#1F1F1F` / `#F3F3F3`），系统只在右上角叠画三个按钮；按钮保持透明底，前景按主题取白/深色。标题栏固定 32dip 高度（**不可**用 `AppWindow.TitleBar.Height` 覆盖，该值是物理像素，150% 缩放下会导致文字看似贴底对齐），并按 `RightInset` 预留右侧空间避免内容压到按钮。

**验证**：用户确认深色下未悬停/悬停/未聚焦三种状态配色均正常，图标与文字和右侧按钮垂直居中。

## 7. 窗口尺寸偏小与位置不记忆 → 已解决

**现象**：150% 缩放的主屏上窗口偏小（逻辑约 507×427），需每次手动拉大。

**原因**：构造函数里在窗口与显示器关联之前调用 `GetDpiForWindow`，返回 96（scale=1.0），于是 `Resize(760 × scale, 640 × scale)` 实际按 760×640 **物理像素**建窗。

**环境（用户双屏，均为 150% 缩放）**：主屏 3840×2160（逻辑 2560×1440，工作区约 2560×1400）、副屏 1440×2560 竖屏（逻辑 960×1707）。

**修复**：尺寸计算移到窗口加载后，使用 `Root.XamlRoot.RasterizationScale` 与**窗口所在显示器**的工作区（`DisplayArea.GetFromWindowId(..., Fallback.Nearest)`）；默认逻辑尺寸提升为 **860×740**，夹取到工作区（保留 40px 边距，最小 480×360）；新增窗口状态记忆，关闭时把物理矩形写入 `%LOCALAPPDATA%\ImgZip\window-state.json`，启动时若该矩形仍在可见显示器内（`DisplayArea.GetFromPoint`）则恢复并夹取，否则回退默认并居中。位置策略：**跟随上次位置**。

**验证**：首启 860×740 逻辑（150% → 1290×1110 物理，居中）；关窗写入 `{"X":1275,"Y":555,"W":1290,"H":1110}`；重开恢复到同一位置与尺寸。

## 8. 已完成任务残留为“状态待确认” → 已解决

**现象**：完成一次任务后重开窗口，上一次已成功的任务仍在列表里显示“状态待确认”。

**现场证据**：`%LOCALAPPDATA%\ImgZip\tasks\f83da2dc….json` 残留，而 `active-job.json` 已正确删除。

**原因**：`RunTaskAsync` 在 `await worker.ExecuteAsync(...)` 返回后立即检查 `task.TerminalConfirmed`，但终态事件是经 `dispatch(...)` 投递到 UI 线程的，await 返回时事件可能尚未执行 → 判定未终态 → 跳过删除 `tasks/<id>.json`；随后 `Mirror()` 删掉了 `active-job.json`，但已无人清理任务记录，于是下次启动被恢复成 unknown。

**修复**：新增幂等的 `FinalizeTaskAsync(task)`（`Finalized` 标志防重复），在终态事件应用之后立即收尾——删除 `tasks/<id>.json`；`succeeded / dryRun / emptyResult` 移出任务列表，`failed / partial / cancelled / unknown` 保留；三个执行路径尾部保留幂等兜底调用。用户机器上那条残留记录已清除。

**验证**：新增回归用例“成功任务收尾后列表为空且任务记录被删除”，测试总数 15 项全部通过。

## 9. 应用图标缺失 → 已解决

**现象**：资源管理器/任务栏显示 WinUI 默认占位图标。

**素材**：`icon/` 目录——`compress-icon.svg`（矢量源）、`compress-icon-1024.png`、`compress-icon.ico`（7 帧：16/24/32/48/64/128/256）、`compress-icon-preview.png` 与生成脚本 `build_icon.py`。设计：`#6C357C` 紫底圆角徽章 + 白色双向箭头，纯扁平、无文字、小尺寸可辨识。

**接入三处**：`ImgZip.App.csproj` 用 `<ApplicationIcon>..\..\icon\compress-icon.ico</ApplicationIcon>` 内嵌进 exe（资源管理器/任务栏/开始菜单都取它）；自绘标题栏左侧改为 `<Image Source="Assets/app-icon.png">`（PNG 以 `Content` 随发布复制）；`installer/ImgZip.iss` 增加 `SetupIconFile=..\icon\compress-icon.ico`。

**验证**：安装 0.3.3 后 exe 图标中心像素 R=105 G=49 B=121（设计色 `#6C357C` = 108,53,124，差异来自 32px 缩放抗锯齿），安装包图标同样生效，标题栏图标资源已随发布复制。

**附带修正**：`.gitignore` 原本的 `*.png` 会连图标一起忽略，现改为仅忽略仓库根目录样张并显式放行 `icon/*.png`。
