# ImgZip 修复记录（0.3.3 → 0.3.4）

范围：0.3.3 检查报告的 7 项问题。状态：代码修复与非视觉回归已通过；0.3.4 的 Windows 编译、安装、真实双引擎、视觉与交互仍待用户验收。

保留 0.3.3 的标题栏、图标、窗口位置记忆、多任务界面、PC 组批与 NAS 并发作业优化，不修改压缩算法及 PowerShell JSON v1 协议。

| # | 问题 | 0.3.4 修复 |
| --- | --- | --- |
| 1 | 排队任务移除后，等待仍继续，释放名额时可能启动 | 每项独立取消令牌；移除终止等待，预留名额后及调用执行层前再检查取消 |
| 2 | unknown 不再被计入运行状态，PC/NAS 可能突破并发限制 | 名额与界面状态分离，已启动 unknown 持续占用，确认终态才释放；分配与转换串行处理 |
| 3 | 草稿可编辑性、关闭判断依赖单个任务 State | 初始化后草稿可编辑，提交保存快照；关闭检查所有任务，“取消并等待”先停止全部排队等待，再取消/检查活动任务 |
| 4 | 失败详情及输出按钮缺少派生属性通知 | 补齐 Failures → HasFailures、OpenOutputPath → CanOpenOutput 通知；逐任务显示错误 |
| 5 | PC 结果未回填可打开的输出目录 | PC 使用事件 Output，NAS 使用映射后的 OpenOutput，路径赋值后及时刷新按钮 |
| 6 | 未启动排队任务重启后成为无法继续的 unknown | 本地 v2 保存请求、阶段、时间与终态；queued 手动继续/移除，launching/running 待检查，finished 幂等收尾；先原子保存 launching，失败则不启动 |
| 7 | 旧 active-job 未真正注册为可检查任务 | 按 ID 合并迁移旧 tasks 与 marker；旧记录保守待检查，新记录写入成功才清理入口，异常提示并保留 |

配套修复：等待已投递事件应用后结束观察，保存终态再幂等清理，迟到事件不覆盖已确认结果；修正 NAS 调度测试在 Mac 上可能零任务也通过的问题。

## 恢复行为

- 新版明确 `queued` 的任务：重启后“等待手动继续”，不自动压缩；用户点击“继续”才重新排队，点击“移除”取消并清理。
- `launching/running` 与缺少阶段的旧任务：待检查并占用名额；不能根据日志不存在认定未启动。
- 已确认终态：保存最终事件与失败详情后幂等清理。成功、预演、空结果自动移出列表；部分失败、失败、取消保留当前窗口中的结果。
- 无法保存或清理记录：显示错误，不静默丢弃原记录；未知任务不能靠关闭 SSH 或删除记录视为已停止。

## 检查结果

原有 15 组与新增 16 组，共 **31 组通过**。覆盖竞争取消、名额保留/释放、手动恢复、迁移与故障注入、草稿快照、关闭汇总、派生通知及幂等终态。旧 NAS 调度测试已修正平台差异，明确验证两项 NAS 请求真实执行、串行运行且可与 PC 并行。

锁定依赖还原、原生 C# 引用程序集类型检查、PowerShell/Bash 语法、XAML/XML 静态检查通过。Mac 类型检查工具补齐 ToggleButton 的 Primitives 命名空间；工具中的 XAML 字段替身与引用统一警告不构成 Windows 构建或运行验证。完整 XAML 构建在 Mac 上受 Windows 专用编译器限制，未生成安装包。

本版本只提交源码，不创建 GitHub Release、不触发 CI、不上传安装程序。Windows 构建命令和逐项验收见 [WINDOWS.md](WINDOWS.md) 与 [VALIDATION.md](VALIDATION.md)。
